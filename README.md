# netmon — 零依赖 Windows 常驻网络监测工具

只用 **Python 标准库 + Windows 自带命令**（`ping` / `ipconfig` / `netsh`），持续监测网关连通性、延迟、丢包、WiFi 信号和真实下载网速：原始数据落盘 CSV，同时自动生成一个 **5 秒自刷新的 HTML 实时看板**。

适合诊断家庭 / 办公室网络不稳定、热点频繁掉线等问题；因为不安装任何第三方包，在装不了软件的公司受管电脑上也能直接跑。

## 功能

- **每秒 ping 网关**：解析 `ping.exe` 中英文输出（GBK / UTF-8 双解码），区分正常 / 超时 / 传输失败，提取延迟毫秒数
- **断链检测**：连续 2 次失败即记「断链开始」，恢复时记「断链恢复」并统计持续时长
- **HTTP 探测**：默认每 15 包请求一次外网 URL，区分「网关通但上不了外网」的情况
- **真实测速**：定时从 CDN 限时下载（默认每 5 分钟、最多下 10 秒），特意直连绕过系统代理，得到真实带宽
- **WiFi 信息采集**：`netsh wlan show interfaces` 获取 SSID / 信道 / 接收速率 / RSSI；**信道变化会记事件**（往往意味着热点重启）
- **实时看板**：纯静态 HTML + 原生 canvas 绘图，无需 Web 服务器和任何前端库，支持 5 分钟 / 30 分钟 / 1 小时 / 12 小时四档窗口（12 小时档按 30 秒聚合），支持暗色模式
- **历史运行对比**：看板内置数据源下拉框，可在「当前（实时）」与任意一次历史运行（`runs/ping_*.csv`，每份自动聚合为至多 720 个点）之间切换，方便复盘之前的问题
- **小白友好的指标说明**：看板上每个指标和图表旁都有「?」弹窗，用通俗语言解释指标含义与判读标准（点击打开，Esc 关闭）
- **数据留存**：每次运行一组 CSV，可长期对比；写入带重试（容忍安全软件短暂锁文件），看板用临时文件 + `os.replace` 原子替换
- **进程体检**：附带 `proc_check.py`，一眼确认监测脚本是否还活着

## 环境要求

- Windows 10 / 11
- Python 3.8+（仅标准库，开发环境为 3.13）

## 快速开始

双击 `启动监测.bat`（或 `start_netmon.bat`），然后用浏览器打开目录下生成的 `netmon_live.html`。

命令行方式：

```bash
python netmon.py                          # 一直跑，Ctrl+C 停止
python netmon.py --minutes 30             # 跑 30 分钟后自动停
python netmon.py --gateway 192.168.1.1    # 手动指定网关（默认自动识别）
python netmon.py --speed-every 0          # 关闭测速，只做 ping 监测
```

## 命令行参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--gateway` | 自动识别 | 要监测的网关 IP |
| `--interval` | `1.0` | ping 间隔（秒） |
| `--http-every` | `15` | 每 N 包做一次 HTTP 探测 |
| `--http-url` | `https://www.qq.com/` | HTTP 探测目标 |
| `--speed-every` | `300` | 测速间隔（秒），`0` 关闭 |
| `--speed-url` | 腾讯 CDN 微信安装包 | 测速下载 URL |
| `--speed-seconds` | `10` | 单次测速最长下载时间（秒） |
| `--minutes` | `0` | 运行时长（分钟），`0` 表示一直跑 |
| `--chart-window` | `3600` | 走势图最多保留的采样点数（1 点 ≈ 1 秒） |

## 输出

```
runs/ping_YYYYmmdd_HHMMSS.csv     每包原始采样：time, seq, ok, ms, kind, channel, rssi
runs/speed_YYYYmmdd_HHMMSS.csv    测速记录：time, mbps, mb_downloaded
netmon_live.html                  实时看板（每 10 包自动重新生成）
```

`runs/` 与看板文件均为运行产物，已在 `.gitignore` 中排除，不会进入仓库。

## 看板说明

顶部徽章基于最近 300 包（约 5 分钟）自动给出结论：

| 结论 | 判据 |
|---|---|
| 🔴 当前断链中 | 正处于连续失败状态 |
| 🟠 链路不稳定 | 丢包率 > 2% 或 >150ms 尖峰超过 3 次 |
| 🟠 有尖峰，可开会但会顿 | 峰值延迟 > 150ms |
| 🟢 链路正常 | 其余情况 |

页面还包含：丢包率 / 平均延迟 / 峰值延迟 / 尖峰次数 / 最新网速五张统计卡片，延迟走势图（灰色缺口＝丢包、红点＝超 150ms；右上角可在「当前（实时）」与任意历史运行之间切换数据源），网速走势图与测速明细表，断链 / HTTP 探测 / 信道变化事件表，以及当前 WiFi 链路信息。每个指标和图表旁的「?」会弹出通俗解释，方便不熟悉网络指标的读者判读。

## 进程体检

双击 `查看进程.bat`（或 `python proc_check.py`），输出五项内容：

1. 所有 Python 进程及完整命令行（PowerShell CIM 获取，失败降级 tasklist），标出哪个是 netmon.py 及其内存占用
2. netmon.py 是否在运行
3. 看板心跳：从 `netmon_live.html` 提取「最近刷新」时间，超过 20 秒未更新即提示脚本可能已停止
4. 最新 ping / speed CSV 的行数与最后一条记录
5. 在任务管理器中自查资源占用的方法

## 实现要点

- **编码兼容**：`netsh` 输出常为 UTF-8、`ping` 输出常为 GBK，统一逐编码尝试解码，避免中文关键词匹配失败
- **文件锁容忍**：天擎 / DLP 等安全软件会短暂锁定文件，CSV 追加失败时重试 12 次而不是崩溃
- **测速直连**：`ProxyHandler({})` 绕过系统代理，测的是真实链路带宽
- **长跑不膨胀**：内存中的采样列表按窗口上限裁剪；12 小时档图表按 30 秒桶聚合（均值 + 峰值）
- **测速历史连续**：启动时读回 `runs/speed_*.csv` 历史记录，重启后走势图不断档

## 注意事项

- 测速会真实下载文件（默认约 10 秒后主动中断，单次十几 MB），**消耗流量**；可按需调大 `--speed-every`、用 `--speed-every 0` 关闭，或用 `--speed-url` 换成自己的测速文件
- HTTP 探测与测速的目标 URL 可自行替换为业务相关的地址
- 仅支持 Windows（依赖 `ping.exe` / `ipconfig.exe` / `netsh.exe` 的输出格式）
